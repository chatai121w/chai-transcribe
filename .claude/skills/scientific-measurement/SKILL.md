# בדיקות מדעיות עם היסטוריה

המדריך הזה נבנה מתוך חקירה אמיתית שבה אותה עבודה בדיוק נמדדה פעם
ב-584 שניות ופעם ב-45 — **פי שלושה עשר** — ושלוש השערות סבירות
נשללו אחת אחרי השנייה לפני שנמצאה הסיבה.

כל כלל כאן עלה מטעות שנעשתה בפועל.

---

## 1. הבעיה שהכל נבנה סביבה

```
280 מילים      המדידה הראשונה
240 מילים      שינוי כלשהו — "הורע"
265 מילים      תיקון — "השתפר!"   <-- כאן הטעות
```

השורה האחרונה היא התקדמות **מול 240**, אבל **15 מילים מתחת
ל-280** שכבר היה. אפשר לחגוג שיפור עשר פעמים ולסיים מתחת לנקודת
ההתחלה.

> **הכלל הראשון: להשוות תמיד מול השיא ההיסטורי, אף פעם לא מול
> המדידה הקודמת.**

---

## 2. שבעת הכללים

| # | כלל | מה קורה בלעדיו |
|---|------|-----------------|
| 1 | **השוואה מול השיא**, לא מול הקודם | מסתובבים במעגל ולא מתקדמים |
| 2 | **לרשום מה ניסינו ולמה**, לא רק את המספר | חוזרים על ניסיון שנפל כעבור חודשיים |
| 3 | **לבדוק לפני ניסיון** שלא נוסה כבר | מבזבזים שבוע על משהו ידוע |
| 4 | **לקשור כל מדידה לנקודת שמירה בגיט** | יודעים שהיה טוב יותר, לא יודעים ממה |
| 5 | **לשמור רשימת חבילות מלאה** | התקנה משדרגת תלות בשקט ושוברת משהו רחוק |
| 6 | **לנטר את מצב המחשב בזמן המדידה** | מודדים את העומס במקום את המערכת |
| 7 | **אם ירדנו — לחזור, לא לתקן** | "תיקון" שמחזיר ל-265 כשהיינו ב-280 הוא המעגל |

## 3. סדר העבודה

```
0.  לבדוק שלא ניסינו את זה כבר        --check-before "תיאור"
1.  לרשום את ההשערה — לפני, לא אחרי
2.  לשמור בגיט
3.  למדוד, ולשמור ביומן               --save "שם"
4.  לעשות את השינוי
5.  למדוד שוב, ולרשום מה למדנו
6.  להשוות מול השיא                   --compare "שם"
7.  אם ירדנו — לחזור
```

**הצעד הראשון חשוב בפני עצמו.** ההשערה נרשמת **לפני** הניסיון. אחרי
שרואים את התוצאה קל לשכנע את עצמך שזה בדיוק מה שציפית, והלקח
מאבד את ערכו.

**הצעד השביעי הוא הקשה.** הנטייה היא לתקן את מה שנשבר. אבל תיקון
שמחזיר ל-265 כשהיינו ב-280 אינו תיקון — הוא המעגל. עדיף לחזור
לנקודה הטובה ולנסות דרך אחרת.

## 4. שלושה מבחנים, כי לאף אחד אין מספיק כוח

### מבחן מובהקות מצרפי

האם ההפרש חורג מהרעש. **חולשתו מדודה**: במדגם של 340 מילים הוא
מסמן רגרסיה רק מ-26 מילים ומעלה.

| מילים במדגם | ההפרש הקטן ביותר שאפשר לזהות |
|---|---|
| 21 | 30.2 נקודות אחוז |
| 100 | 13.9 |
| 340 | 7.6 |
| 1000 | 4.4 |

**ירידה של 20 מילים מתוך 340 חומקת מהמבחן הזה.**

### השוואה מזווגת, פריט מול פריט

זה המבחן החזק. אותו מנוע על אותם פריטים — ההשוואה מזווגת, ולכן
אפשר לראות בדיוק מה ירד.

**בשינוי סביבה** — החלפת ספרייה, מעבר לכרטיס מסך — הפלט אמור
להישאר **זהה**. כל שינוי שם הוא סימן, גם אם הסכום לא זז.

### פריט שנשבר

פריט שאיבד יותר ממחצית מהתוצאה מסומן כ**בעיה**, לא כהערה — בלי
קשר למובהקות. פריט שנפל מ-17 ל-0 לא "הורע קצת".

## 5. ניטור המחשב — בלעדיו מדידת מהירות חסרת ערך

**הממצא שהוביל לזה:** אותה עבודה בדיוק נמדדה פי שלושה עשר לאט
יותר. שלוש השערות נשללו — טעינת המנוע, תפיחת זיכרון בכרטיס, האטה
מחום — עד שהתברר שהמעבד היה עמוס 75 אחוז, ומעל 60 אחוז ב-88 אחוז
מהזמן.

כל מדידה חייבת לרשום:

| מה | למה |
|---|---|
| מעבד — ממוצע, שיא, וכמה מהזמן היה עמוס | ממוצע לבדו מסתיר עומס קצר וחזק |
| זיכרון פנוי — מינימום | מחסור גורם לגלישה לדיסק |
| הכרטיס — ניצול, זיכרון, חום, תדר | כולם משפיעים |
| **סיבות האטה** | כרטיס נייד מואט בהגבלת חשמל, בלי הודעה |
| תוכנות כבדות שרצות במקביל | זה מה שמסביר את הפער |

### ההבחנה החשובה ביותר

> **עומס משפיע על המהירות, לא על הדיוק.**
>
> מנוע עמוס עונה את **אותה תשובה בדיוק**, רק לאט יותר.

הוכחה שנמדדה: שלוש מדידות באותם תנאי קוד, בעומס שונה לגמרי.

| מדידה | דיוק | מהירות |
|---|---|---|
| ראשונה | 272/349 | 3.223 |
| שנייה | 272/349 | 0.248 |
| שלישית | 272/349 | 0.328 |

**הדיוק מילה במילה זהה. רק המהירות זזה פי 13.**

לכן: **מדידה תחת עומס מסומנת כלא ניתנת להשוואה במהירות — והדיוק
שלה נשאר תקף.**

## 7. מה לעשות בפועל

הכלים בפרויקט הזה:

```bash
# לפני ניסיון — לבדוק שלא נוסה כבר
python scripts/regression_check.py --check-before "מה שעומדים לנסות"

# למדוד ולרשום
python scripts/regression_check.py --save "שם" \
    --hypothesis "מה ציפינו ולמה" \
    --change "מה בדיוק שונה" \
    --outcome "מה קרה" \
    --learned "מה למדנו ומה לא לנסות שוב" \
    --verdict אומץ|נפסל|"לא הוכרע"

# להשוות מול השיא
python scripts/regression_check.py --compare "שם"

# בשינוי סביבה — כל שינוי בפלט הוא סימן
python scripts/regression_check.py --compare "שם" --environment-change

# לראות הכל
python scripts/regression_check.py --history
python scripts/regression_check.py --lessons

# מצב המחשב
python scripts/machine_state.py
python scripts/machine_state.py --watch 30
```

## 9. חמשת הכללים לניסוח

כשמדווחים תוצאה:

1. **מספרים מוחלטים, לא רק אחוזים.** "272 מתוך 349" ולא "78 אחוז".
   אחוז לבדו מסתיר את גודל המדגם.
2. **רווח סמך תמיד.** "78% (73.3 עד 82.0)".
3. **לומר במפורש כשההפרש בתוך הרעש.** "ההפרש 15 מילים, גבול הרעש
   26 — אי אפשר להסיק."
4. **להפריד דיוק ממהירות.** הם לא אותה רמת אמינות.
5. **לתקן מספר שגוי מיד ובמפורש.** "המספר שנתתי קודם היה מזוהם;
   המדידה הנקייה נותנת X."
