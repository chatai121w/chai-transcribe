# איך לא להסתובב במעגל

נכתב ב-24 באוקטובר 2026.

הבעיה: רגרסיה, התקדמות, רגרסיה, התקדמות — ובסוף לא מתקדמים לשום מקום.

המסמך מתאר את המנגנון שבנינו כדי שזה לא יקרה, ואיך משתמשים בו.

---

## הטעות שגורמת למעגל

```
מדידה ראשונה    280 מילים
שינוי כלשהו     240 מילים      "הורע"
תיקון           265 מילים      "השתפר!"  <-- כאן הטעות
```

השורה האחרונה נראית כהתקדמות, והיא באמת התקדמות **מול 240**. אבל
אנחנו **15 מילים מתחת ל-280** שכבר היה לנו. אם נמשיך להשוות לקודם,
נוכל לחגוג שיפור עשר פעמים ולסיים מתחת לנקודת ההתחלה.

**הפתרון: להשוות תמיד מול השיא ההיסטורי, אף פעם לא מול הקודם.**

## המנגנון

### יומן אחד, לכל ההיסטוריה

כל מדידה נרשמת בקובץ אחד, שורה לכל מדידה:

```
benchmark_private/regression/journal.jsonl
```

ובו נשמר לכל מדידה:

| מה | למה |
|---|---|
| כמה מילים נכונות מתוך כמה | המספר עצמו |
| מתי | לסדר הזמנים |
| **נקודת השמירה בגיט** | **כדי לדעת איזה קוד הפיק את זה** |
| האם היו שינויים לא שמורים | אם כן — המדידה אינה ניתנת לשחזור |
| גרסאות הספריות | כדי לדעת אם הסביבה השתנתה |
| מה רץ על כרטיס המסך | כדי לדעת אם זה הבדל מהירות או דיוק |

**נקודת השמירה היא החלק החשוב.** בלעדיה מספר הוא רק מספר. איתה,
השיא מצביע על מצב קוד מדויק שאפשר לראות ולחזור אליו.

### שלושה מבחנים, כי לאף אחד אין מספיק כוח

**1. מבחן מובהקות מצרפי.** האם ההפרש חורג מהרעש.

חולשתו: הוא מניח שתי מדידות עצמאיות. במדגם של 340 מילים הוא מסמן
רגרסיה רק מ-26 מילים ומעלה. **ירידה של 20 מילים הייתה חומקת ממנו.**

**2. השוואה מזווגת, קטע מול קטע.** אותו מנוע על אותם קטעים.

זה המבחן החזק. אם קטע מסוים ירד, רואים בדיוק איזה. שינוי בסביבה —
החלפת ספרייה, מעבר לכרטיס מסך — אמור להשאיר את הפלט **זהה**. כל
שינוי שם הוא סימן, גם אם הסכום לא זז.

**3. קטע שנשבר.** קטע שאיבד יותר ממחצית מילותיו מסומן כבעיה ולא
כהערה — בלי קשר למובהקות. קטע שנפל מ-17 ל-0 לא "הורע קצת".

## יומן הלקחים — החלק החשוב ביותר

מספר אומר **שמשהו קרה**. הוא אינו אומר **מה ניסינו ולמה**.

בלי זה נחזור על ניסיון שכבר נכשל כעבור חודשיים, כי אף אחד לא יזכור
שהוא נוסה. לכן לכל מדידה נרשמים ארבעה שדות:

| שדה | על מה הוא עונה |
|---|---|
| **השערה** | מה ציפינו שיקרה, ולמה חשבנו כך |
| **שינוי** | מה בדיוק שונה |
| **תוצאה** | מה קרה בפועל |
| **לקח** | מה למדנו — ובעיקר, **מה לא לנסות שוב** |

ובנוסף **הכרעה**: אומץ, נפסל, או לא הוכרע.

דוגמה אמיתית מהיומן:

> **מנועי יידיש — נפסל**
> **השערה:** יידיש קרובה פונטית לאשכנזית ושומרת מילים עבריות בכתיב
> מסורתי, ולכן מנוע יידיש אמור לזהות הגייה אשכנזית טוב יותר.
> **תוצאה:** פי שלושה עד חמישה גרוע יותר מהבסיס.
> **לקח:** המנוע מחליף מילים עבריות במילים ביידיש ונכנס ללולאות.
> קרבה פונטית אינה מספיקה — המילון שונה.

**הלקח שווה יותר מהמספר**, כי הוא מונע את הניסיון הבא.

### השומר — עוצר לפני שחוזרים על ניסיון שנפל

יומן לבדו עוזר רק למי שזוכר לקרוא אותו. לכן יש בדיקה שרצה **לפני**
הניסיון:

```bash
python scripts/regression_check.py --check-before "מה שעומדים לנסות"
```

היא מחפשת ביומן ניסיונות דומים, ואם משהו כבר נפסל — עוצרת ומראה
למה. ההתאמה לפי מילים משותפות, ולכן היא תופסת גם ניסוח אחר של
אותו רעיון: "להקליט קול מלאכותי" ו"הקראה סינתטית" נתפסים כאותו דבר.

היא אינה חוסמת בכוח. אבל אם ממשיכים — צריך לומר **מה שונה הפעם**,
אחרת זה אותו ניסיון עם אותה תוצאה.

### מה כבר רשום

שבעה ניסיונות מהעבודה שנעשתה עד כה, כולם מסומנים כנפסלו:

| ניסיון | הלקח בקצרה |
|---|---|
| מנועי יידיש | קרבה פונטית אינה מספיקה — המילון שונה |
| מנוע ישיביש | כוונון לתחום יכול לצמצם את היכולת הכללית |
| מנוע קבלה | הפסיד בשתי הרמות |
| אימון על קול מלאכותי בלבד | מזיק. תערובת כן עוזרת |
| כל מונחי לשון הקודש ברשימה | לחלון המונחים יש גבול |
| חולם כ-OY | זאת הצורה הפולנית, לא הליטאית |
| המקודד הכבד | היה גרף מוכן קטן פי ארבעה |

## איך משתמשים

### לפני כל שינוי משמעותי

```bash
git add -A && git commit -m "לפני השינוי"
python scripts/regression_check.py --save לפני-השינוי
```

השמירה בגיט **לפני** המדידה חשובה: מדידה שנלקחה כשיש שינויים לא
שמורים אינה ניתנת לשחזור, והכלי יסמן אותה ככזאת.

### אחרי השינוי

```bash
python scripts/regression_check.py --save אחרי-השינוי
python scripts/regression_check.py --compare אחרי-השינוי
```

כשהשינוי היה בסביבה בלבד — ספרייה, גרסה, כרטיס מסך — מוסיפים דגל:

```bash
python scripts/regression_check.py --compare אחרי-השינוי --environment-change
```

אז **כל** שינוי בפלט מסומן כבעיה, ולא רק ירידה מובהקת. שינוי ספרייה
אינו אמור לשנות מה שהמנוע שומע.

### לראות את כל ההיסטוריה

```bash
python scripts/regression_check.py --history
```

מציג את כל המדידות לפי סדר, עם סימון השיא.

## מה קורה כשיש רגרסיה

הכלי מדפיס שלושה דברים:

**1. כמה ירדנו מול השיא** — ולא מול הקודם.

**2. מה השתנה מאז.** רשימת השמירות והקבצים בין נקודת השיא לעכשיו:

```
12 שמירות מאז:
   a1b2c3d שינוי בהגדרות הפענוח
   ...
8 קבצים השתנו:
   M  server/config.py
   ...
```

**3. איך חוזרים:**

```bash
git diff <נקודת-השיא>..HEAD --stat
git switch -c חזרה-<נקודה> <נקודת-השיא>
```

החזרה היא **לענף נפרד** ולא דריסה. מה שיש עכשיו נשמר.

## הגיבוי — מה גיט כבר עושה, ומה לא

### מה גיט עושה אוטומטית

כל שמירה היא נקודת חזרה מלאה. שום דבר שנשמר אינו אובד, גם אחרי
מחיקה. ולכן **הכלל: לשמור לפני כל שינוי משמעותי** — אחרת אין לאן
לחזור.

### מה גיט אינו עושה

| מה | למה לא | מה כן עושים |
|---|---|---|
| משקולות המנועים | מעל 100 מגה לקובץ — גיטהאב חוסם | מוחרגות, ויורדות מחדש בשתי פקודות |
| קבצי הקלטה | פרטי, וכבד | מוחרג |
| גרסאות הספריות | אינן בקוד | **נרשמות ביומן המדידות** |

הנקודה האחרונה חשובה: עדכון ספרייה יכול לשבור דברים בלי לשנות שורת
קוד אחת. לכן היומן רושם את הגרסאות, והקובץ `before.txt` שומר רשימה
מלאה לשחזור:

```bash
pip install -r before.txt
```

## כלל העבודה

```
0. לבדוק שלא ניסינו את זה כבר     --check-before
1. לרשום את ההשערה — לפני, לא אחרי
2. לשמור בגיט
3. למדוד ולשמור ביומן
4. לעשות את השינוי
5. למדוד שוב, ולרשום מה למדנו
6. להשוות מול השיא
7. אם ירדנו — לחזור, לא "לתקן"
```

**הצעד הראשון חשוב בפני עצמו.** ההשערה נרשמת לפני הניסיון, ולא
אחריו — אחרי שרואים את התוצאה קל לשכנע את עצמך שזה בדיוק מה
שציפית, וכך הלקח מאבד את ערכו.

**הצעד השישי הוא הקשה.** הנטייה הטבעית היא לנסות לתקן את מה שנשבר.
אבל תיקון שמחזיר אותנו ל-265 כשהיינו ב-280 אינו תיקון — הוא בדיוק
המעגל. עדיף לחזור לנקודה הטובה ולנסות דרך אחרת.

## מה הכלי אינו יכול

**המדגם קטן.** 340 מילים. המבחן המצרפי תופס רק ירידות גדולות.
ההשוואה המזווגת מפצה על זה חלקית, אבל לא לגמרי. **מדגם גדול יותר
הוא השיפור הגדול ביותר שאפשר לעשות כאן.**

**רק עברית רגילה נמדדת.** אין עדיין מדגם מאושר לשיעור תורה ולהגייה
אשכנזית. רגרסיה דווקא שם לא תיתפס.

**המדידה אינה כוללת את כל המערכת.** היא מודדת תמלול, הקראה, ניקוד
ושכפול קול. עריכה, תרגום וזיהוי דוברים אינם נמדדים.
